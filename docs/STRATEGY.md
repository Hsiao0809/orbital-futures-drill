# ORBITAL 產品與商業規劃

本文件記錄產品定位、差異化來源與商業化路徑。實作進度以 README 為準。

---

## 1. 問題

Prop firm（自營交易資金商）考試的通過率長期偏低，多數業者公布或第三方估算都落在
個位數到十幾個百分點之間。考試費用一次數十到數百美元不等，重考要再付一次。

關鍵觀察：**絕大多數失敗不是因為看錯方向。**

考試的判定條件本身就是風控條件——日虧損上限、最大回撤、一致性條款、最低交易日。
一個勝率不錯但部位算錯的人，會在某一天的單筆交易上直接出局；一個穩定小賺的人，
可能因為某天賺太多而違反一致性條款。這些都與「預測能力」無關。

因此市面上大量的「看盤訓練」「K 線猜漲跌」工具，訓練的是一個與通過考試相關性很低的技能。

---

## 2. 產品定位

> **花時間在這裡失敗，不要花考試費去失敗。**

這不是「教你賺錢」的產品——那是一條法規與信任上都不該碰的紅線，而且無法驗證。
這是一個**降低重考次數期望值**的工具，價值可以直接被使用者換算成金錢：

- 買家的替代方案是「直接去考，失敗再重考」
- 如果訓練能讓平均重考次數下降，價值就等於省下的考試費
- 這個帳使用者自己會算，不需要我們做任何獲利承諾

## 3. 差異化：為什麼別人做不出來

大多數同類工具停在「回放歷史 K 線 + 記錄損益」。真正難的、也是本產品的核心資產，
是 `lib/engine/propRules.ts` 那一層：

1. **回撤模式的正確建模**
   靜態回撤與追蹤式回撤是完全不同的遊戲。追蹤式回撤（死亡線跟著權益高點上移）
   會製造「帳面還在賺錢，但距離出局只剩一點點」的狀態，這是最多人栽跟頭的地方，
   也是幾乎沒有訓練工具正確模擬的地方。

2. **未實現損益是否計入上限**
   計入的規則檔會在你睡覺時因為浮虧而判你違規。「沒平倉就不算虧」這個誤解，
   在真實考試中價值數百美元。

3. **即時風險預算**
   不是事後告訴你違規了，而是在下單前就顯示「你還剩 78 U，這筆單風險 49 U，
   佔剩餘空間 64%」。這個數字必須由完整的規則引擎即時算出，不能寫死。

4. **悲觀假設**
   同根 K 線同時觸及停損停利判停損、跳空以開盤價成交、限額用影線判定。
   一個會奉承使用者的模擬器會給出錯誤的信心，比沒有模擬器更糟。

5. **行為診斷**
   從交易紀錄反推並命名 11 種具體壞習慣，附證據數字。這是把「你虧了 4%」
   轉換成可執行動作的那一步。

護城河不在 UI，在這些規則的正確性與完整性上。UI 可以被複製，
但要正確建模四種回撤模式並通過 105 項測試，是需要真的懂這件事才做得出來的。

## 4. 目標使用者

| 分群 | 特徵 | 需求 |
|---|---|---|
| **首考者** | 有交易經驗，沒考過 prop firm | 不知道規則細節會怎麼殺死自己 |
| **重考者**（最高付費意願） | 已經失敗一到多次 | 知道自己輸在哪裡，但不知道怎麼改 |
| **已通過、管理實盤帳戶者** | 有資金帳戶，怕違規失去 | 一致性與回撤管理的持續練習 |

重考者是最好的起點：他們剛付出過真實成本，痛感新鮮，且明確知道自己需要什麼。

## 5. 商業化路徑（尚未實作）

本輪刻意不做付費牆，先把產品核心做對。但資料模型（`db/schema.ts`）與
權限接縫已預留，之後接上不需要重寫。

**分層構想**

| 方案 | 內容 | 定位 |
|---|---|---|
| Free | 每日限量題數、單一規則檔、不保留歷史 | 漏斗入口，也是誠意 |
| Pro | 全部題型與規則檔、完整考試模擬、行為診斷報告、雲端同步 | 主要營收 |
| Team | 多人進度看板 | 給有教育訓練需求的交易社群 |

**獲客假設**

- **可分享的種子碼**：同一題目可以丟給朋友挑戰，天然傳播
- **免費診斷漏斗**：「你能通過 FTMO 嗎」形式的短測驗，結果頁導向完整訓練
- **社群**：prop trading 的 Discord / Reddit / X 社群，痛點高度集中
- **內容**：把規則引擎的知識寫成文章（例如「追蹤式回撤如何在你獲利時殺死你」），
  這類內容本身就在展示產品的專業度

**不做的事**

- 不做交易訊號、不做跟單、不做代操
- 不承諾通過率或獲利
- 不宣稱模擬任何具名業者的當前條款（條款會變，這是負債不是資產）

## 6. 產品原則

1. **誠實高於好用**。準備度分數明確標示為「訓練完成度，不是通過機率」。
   所有成本假設都在 UI 上寫明是建模估算。
2. **遊戲化要有牙齒**。只會上升的點數不教任何東西。能力值會下降，關卡會鎖住。
3. **風控排在判讀之前**。訓練階梯刻意把部位計算放在第一階、行情判讀放在第三階。
4. **local-first**。沒有帳號、沒有資料庫也要能完整使用。
5. **可重現**。每個情境都由種子決定，任何一題都能重播與分享。

## 7. 已知限制

- **行情資料單一來源**：目前只有 Binance USDⓈ-M 永續合約，且部分地區 IP 會被
  以 HTTP 451 拒絕。若要支援外匯／指數／美股期貨的 prop firm，需要新的資料源。
- **資金費率為建模值**：使用固定費率而非歷史實際費率。長線持倉的成本會有偏差。
- **無盤中 tick 資料**：只有 OHLC，因此盤中順序無法還原，以悲觀假設處理。
- **單一標的考試**：考試模擬目前一次只跑一個合約，不支援多標的組合。
- **付費機制未實作**：定價與金流是下一階段的工作。
